> Назначение файла: описывает выбор штатного каталога, демонстрационный склад, тестовые запчасти и правила количественного учёта модуля.

# Каталог запчастей

## 1. Выбор каталога

Миграция `202608090008` использует основной товарный каталог CRM, возвращаемый штатным API `CCrmCatalog`. Если каталог ещё не создан, CRM создаёт собственный каталог стандартным способом. Модуль не создаёт параллельный изолированный инфоблок, поэтому добавленные в него запчасти доступны в товарных позициях сервисных сделок.

ID выбранного инфоблока сохраняется в настройке модуля `spare_parts_catalog_id`. Каталог принадлежит CRM и никогда не удаляется при откате `otus.autoservice`.

## 2. Свойство артикула

В выбранном каталоге создаётся одиночное строковое свойство:

- название — «Артикул автосервиса»;
- код — `OTUS_AUTOSERVICE_ARTICLE`;
- внешний ID — `OTUS_AUTOSERVICE_ARTICLE_PROPERTY`.

Внешний ID используется как метка владельца. Если код уже занят несовместимым чужим свойством, миграция останавливается вместо изменения чужой конфигурации. ID свойства сохраняется в `spare_parts_article_property_id`.

## 3. Демонстрационный склад

Модуль создаёт один активный склад:

- название — «Демонстрационный склад автосервиса»;
- код — `OTUS_AUTOSERVICE_DEMO`;
- внешний ID — `OTUS_AUTOSERVICE_DEMO_STORE`;
- сайт — основной активный сайт портала.

Если на портале ещё нет склада по умолчанию, демонстрационный склад получает этот признак. Существующий чужой склад по умолчанию не изменяется. ID сохраняется в `spare_parts_store_id`.

## 4. Необязательные демонстрационные запчасти

Установщик и миграция не создают товары. После установки демонстрационный набор можно добавить только явной командой:

```powershell
php local/modules/otus.autoservice/tools/seed_demo_spare_parts.php --apply
```

Таким образом, производственная установка не получает тестовые данные, а локальная демонстрационная среда воспроизводимо заполняется без ручного создания каждого товара.

Создаются четыре физических товара с включённым количественным учётом и запретом продажи при нулевом остатке:

| Запчасть | Артикул | Внешний ID | Начальное количество без складского учёта |
|---|---|---|---:|
| Фильтр масляный двигателя | `OTUS-OF-001` | `OTUS_AUTOSERVICE_PART_OIL_FILTER` | 6 |
| Комплект передних тормозных колодок | `OTUS-BP-001` | `OTUS_AUTOSERVICE_PART_BRAKE_PADS` | 0 |
| Свеча зажигания | `OTUS-SP-001` | `OTUS_AUTOSERVICE_PART_SPARK_PLUG` | 12 |
| Масло моторное 5W-30, 1 л | `OTUS-EO-530` | `OTUS_AUTOSERVICE_PART_ENGINE_OIL` | 4 |

Для каждого товара создаются:

1. элемент штатного CRM-каталога;
2. запись физического товара `catalog`;
3. коэффициент единицы измерения `1`;
4. связь с демонстрационным складом;
5. уникальные артикул и внешний ID.

Повторное выполнение команды находит сущности по внешним ID и не создаёт дубликаты. Перед сохранением каждого товара команда проверяет артикул по всему CRM-каталогу и останавливается, если он уже принадлежит другому элементу. Существующие количества не сбрасываются. Если при выключенном складском учёте у существующего товара отсутствует строка выбранного склада, она восстанавливается как разница между текущим доступным количеством товара и доступным количеством на остальных активных складах, а не с первоначальным тестовым значением.

## 5. Режимы количественного учёта

Миграция и команда демонстрационного заполнения не включают и не выключают глобальный складской учёт портала.

Если складской учёт выключен, начальные количества новых товаров записываются штатной моделью товара и в строку выбранного склада. Диагностика сравнивает доступное количество товара с суммой `AMOUNT - QUANTITY_RESERVED` только по активным складам. Последующий сервис синхронизации должен поддерживать эту согласованность.

Если складской учёт включён, новые демонстрационные товары создаются с нулевым количеством. Ненулевой приход должен оформляться штатным складским документом. Команда заполнения не подменяет документ прямым изменением остатка. Диагностика проверяет рассчитанное Bitrix доступное количество по активным складам и равенство общего резерва товара сумме `QUANTITY_RESERVED` этих складов.

На следующем этапе внешний поставщик будет возвращать абсолютное текущее количество. Запись полученного значения должна выполняться разными штатными сценариями для включённого и выключенного складского учёта.

## 6. Безопасный откат

При полном удалении данных модуль:

1. не удаляет штатный CRM-каталог;
2. удаляет демонстрационную запчасть только при отсутствии ссылок из товарных позиций CRM и складских документов;
3. сохраняет демонстрационный склад, если на нём остались любые товарные строки или ссылки из складских документов;
4. удаляет свойство артикула только при отсутствии использующих его элементов;
5. очищает только собственные настройки этого этапа.

Такой порядок не повреждает историю уже созданных сделок и данные, которые администратор начал использовать после установки.

## 7. Установка и проверка

Применить обязательную миграцию:

```powershell
php local/modules/otus.autoservice/tools/migrate.php --apply
```

Проверить обязательную конфигурацию без изменения данных:

```powershell
php local/modules/otus.autoservice/tools/check_spare_parts_catalog.php
```

Добавить и проверить необязательные демонстрационные товары:

```powershell
php local/modules/otus.autoservice/tools/seed_demo_spare_parts.php --apply
php local/modules/otus.autoservice/tools/check_spare_parts_catalog.php --require-demo
```

Обычная проверка подтверждает версию миграции, выбор основного CRM-каталога, метки склада и свойства. При наличии демонстрационных товаров дополнительно проверяются товарные записи, единственный коэффициент по умолчанию со значением `1`, складские строки, доступное количество и — при включённом складском учёте — общий резерв. Флаг `--require-demo` делает отсутствие полного демонстрационного набора ошибкой.

Если подготовка инфраструктуры прерывается после создания только части объектов, менеджер компенсирует изменения: удаляет только созданные текущим вызовом и ещё неиспользуемые свойство или склад и восстанавливает прежние значения настроек. Ранее существовавшие объекты с метками модуля такая компенсация не удаляет.
