# Поставщики внешних остатков

Этот документ описывает контракт и встроенные реализации источника внешних остатков, доступные в модуле `otus.autoservice` начиная с версии `0.10.0`.

## Назначение

Поставщик решает только одну задачу: получает проверенные идентификаторы запчасти и возвращает её текущее абсолютное количество во внешней системе. Значение `7` означает «сейчас доступно 7 единиц», а не «прибавить 7 единиц».

Поставщик не выполняет следующие действия:

1. Не изменяет количество товара или остаток склада Bitrix.
2. Не создаёт заявки на закупку.
3. Не записывает запуск в таблицы синхронизации.
4. Не отправляет Push&Pull или IM-уведомления.

Журналирование выполняет `StockSyncService` версии `0.11.0`; изменение штатных остатков и закупки остаются обязанностями следующих этапов.

## Контракт

`StockProviderInterface::getCurrentQuantity()` принимает неизменяемый `StockItem` со следующими полями:

1. Положительный ID элемента CRM-каталога.
2. Непустой внешний ID товара.
3. Непустой уникальный артикул.

Метод возвращает неотрицательное целое количество либо выбрасывает `StockProviderException`. Исключение содержит безопасный машинный тип и признак временной ошибки. `StockBatchFetcher` преобразует ответы поставщика в отдельные `StockFetchResult`, поэтому ошибка одного товара сохраняется в его результате и не мешает запросить следующие товары порции. Неожиданные программные исключения не скрываются.

## RandomOrgStockProvider

Демонстрационная реализация выполняет GET-запрос к фиксированному HTTPS endpoint:

```text
https://www.random.org/integers/?num=1&min=0&max=10&col=1&base=10&format=plain&rnd=new
```

Один ответ рассматривается как абсолютный остаток в диапазоне от `0` до `10`. Реализация:

1. Использует штатный `Bitrix\Main\Web\HttpClient`.
2. Проверяет TLS и запрещает переход к частным IP-адресам.
3. Ограничивает соединение пятью секундами, чтение — десятью секундами, тело — 256 байтами.
4. Разрешает не более двух попыток с короткой задержкой.
5. Повторяет только транспортные ошибки, `408`, `425`, `429` и статусы `5xx`.
6. Не повторяет постоянные HTTP-ошибки и некорректные успешные ответы.
7. Принимает только статус `200`, MIME-тип `text/plain` и ровно одно целое число от `0` до `10`.
8. Распознаёт ответ, начинающийся с `Error:`, как временную ошибку сервиса.
9. Не включает URL, тело ответа и сообщения низкоуровневого транспорта в своё безопасное сообщение.

Endpoint не использует API-ключи. Если в будущем появится поставщик с авторизацией, секрет должен храниться вне репозитория и никогда не передаваться в контекст журнала.

## FakeStockProvider

`FakeStockProvider` не выполняет сетевых запросов. В конструктор передаётся карта количеств, где ключом служит внешний ID или артикул. Приоритет имеет внешний ID, затем артикул, затем единое значение по умолчанию.

Пример:

```php
$provider = new FakeStockProvider(
    [
        'OTUS_AUTOSERVICE_PART_OIL_FILTER' => 0,
        'OTUS-BP-001' => 8,
    ],
    5
);
```

Такой источник нужен для воспроизводимых проверок нулевого остатка, успешного остатка и последующей логики закупок.

## Выбор реализации

В административной странице настроек модуля доступно поле «Источник внешних остатков»:

- `random_org` — демонстрационный HTTP-сервис, выбранный по умолчанию;
- `fake` — локальный источник, возвращающий значение `5`, если отдельная карта не внедрена.

`StockProviderFactory` читает проверенное значение настройки. Её конструктор также принимает список объектов `StockProviderInterface`, поэтому тест или другая поставка может внедрить собственную реализацию без изменения фабрики.

## Проверка

Безопасная локальная проверка не обращается к сети и не изменяет данные:

```powershell
php local/modules/otus.autoservice/tools/check_stock_providers.php
```

Она проверяет автозагрузку, Fake-поставщика, фабрику, корректный plain-ответ, повтор после `503`, отсутствие повтора после `400`, неверный формат, сокрытие тела ошибки и продолжение пакета после ошибки отдельного товара.

Один реальный запрос к Random.org выполняется только с явным флагом:

```powershell
php local/modules/otus.autoservice/tools/check_stock_providers.php --live
```

Команда ничего не записывает в каталог или базу модуля. Ошибка сети возвращает ненулевой код завершения.

## Связь с ежедневной синхронизацией

Начиная с версии `0.11.0`, `StockSyncService` вызывает поставщика для запчастей порциями и сохраняет `StockFetchResult` в журналы синхронизации. Поставщик по-прежнему не знает о базе данных и каталоге. Применение успешного абсолютного количества к товару и складу относится к этапу 5.17. Эксплуатация cron описана в [STOCK_SYNC.md](STOCK_SYNC.md).
